# Codex Ops 贡献指南

[English](CONTRIBUTING.md)

当前插件位于 `packages/codex-ops/`，共享 Rust worker 位于 `native/`。
使用 CI 锁定的 Python 3.14、uv 0.11.32 和 Rust 1.97.1。Node 24 用于仓库检查和
下载集成测试使用的固定 Codex 宿主。

在仓库根目录执行：

```console
npm ci --ignore-scripts
npm run check:size
cargo test --workspace --locked --manifest-path native/Cargo.toml
cargo build --locked --release --manifest-path native/Cargo.toml --bin dsh-ops-worker
cargo test --locked --manifest-path packages/codex-ops/rust-kernel/Cargo.toml
cargo build --locked --release --manifest-path packages/codex-ops/rust-kernel/Cargo.toml
```

把 worker 和内核复制到 `packages/codex-ops/bin/`；Windows 保留 `.exe` 后缀，另执行
`rustc --edition 2024 -O packages/codex-ops/runtime_bridge/shim.rs -o packages/codex-ops/bin/codex-ops-cli.exe`。
然后在 `packages/codex-ops/` 中执行：

```console
uv sync --locked
uv run --locked python -m unittest discover -s tests
```

集成测试需要 CI 固定的 Codex 原生 CLI 和宿主。完整四平台流程见
`.github/workflows/ci.yml`：准备测试夹具，在隔离 Codex home 中安装解压后的插件包并验收。
通过、失败和平台专属跳过分别报告；目录任务测试必须在所有平台通过。

通过 WSL 测试时，把 `UV_PROJECT_ENVIRONMENT` 指向仓库外的 Linux 专用目录，防止替换
Windows 虚拟环境。测试时保留用户现有安装。

PR 关联议题，更新双语文档与 `CHANGELOG.md`，填写 PR 模板。代码文件不超过 1000 行，
实现分片约不超过 1000 新增行。不重写已推送历史。旧 DSH 产品代码和开发快照可从 Git 历史
取回，不参与当前构建。保留原生依赖的 LICENSE/NOTICE。
