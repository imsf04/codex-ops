## 历史配对的条件与限制

引用身份由“报告 SHA256、任务、重复编号、协议、版本”共同确定，不能只凭任务名。设计已绑定84条主基线、六条补充基线、原评估器、冻结源码及运行时；失败行没有被过滤。提示、源文件夹具、LF回执、答案字段与类型、保留检查、oracle 均不改动。

这是**按任务匹配的历史参考比较**，不是新鲜随机交错的三臂试验，也不是相同随机种子。时间、服务负载、缓存热度会变化。保留实际总输入/缓存输入/未缓存输入，不通过折算或扣减凑门槛；分别报告全部尝试、共同成功配对、所有“基线成功而候选失败”的情况，以及各任务/重复结果。耗时只作描述；历史资料缺失的字段保持未知。

复用前应核对原生 CLI/build、模型与推理档、实际沙箱/功能/指令配置、八个工具 schema、按需技能目录和真实 hook 定义/执行。历史目录实际含 **38个技能：37个继承技能和当前版本插件技能**。不能为了简化试验删掉这些继承技能。绝对路径迁移和元数据差异要记录；若重要上下文或协议差异无法消除，历史对比只能作探索参考，不能默称等价，也不应无理由重跑全部84条基线。

旧基线没有自动服务埋点，自动服务率不能写成0。公平比较显式工作流选择；候选自动交付及任务级并集另行报告。保存证据不等于交付证据；没有独立标注的 evidence 工作流机会，不编造分母。

## 原生执行与恢复

整个批次只使用一个新的权威私有目录：`LOCALAPPDATA/CodexOps/acceptance-0.8-next-1/home`。只读引用冻结基线源码，在这个新 home 安装三个原生插件身份，每个进程只启用一个。可沿用已授权的本机不透明 API 认证处理，不输出内容；绝不复制或链接 Windows 的 `.sandbox` / `.sandbox-secrets`。

得到主代理明确执行授权后，仅为这个 home 调用一次官方 Windows 沙箱配置，禁止逐版本配置。先验证真实原生命令与目录/上下文等价，再发起模型调用。审计和 oracle 文件始终放在普通 `C:/Temp` 夹具根目录之外。

此配置会临时轮换机器级沙箱账户凭据，因此恢复是同一批次的组成部分：关闭全部私有 host，用官方接口恢复原全局 home，然后同时检查 readiness 和真正的原生命令。预检失败、取消和试验失败也必须恢复，并保留恢复回执。旧候选源码、旧审阅 profile、标准运行时及用户选择器都不动。

## 全局 home 捷径为何暂不用于验收

官方文档说明了每进程配置覆盖、`CODEX_HOME` 和独立命名 profile 配置文件；profile 不代表独立 Windows 沙箱身份。[高级配置](https://learn.chatgpt.com/docs/config-file/config-advanced)

官方参考提供技能启用和记忆注入控制，但修改开关本身并不能证明与历史38技能目录等价。[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)

本机0.165.0-alpha.1.2的 schema 与惰性测试证明：

- `plugin/install` 没有 `enabled:false` 参数；CLI 拒绝 `--profile … plugin marketplace add`。“全局安装后立即禁用”仍是实际全局变更，可能短暂启用插件。
- `thread/start.selectedCapabilityRoots` 接受外部惰性插件，并原生连接其 MCP 服务和工具，带有指定插件身份。第一次因测试夹具使用旧 MCP SDK 导入而失败，原回执保留；改为 MCP2 后连接成功。
- 通用 `skills/list`、`hooks/list` 没有证明该根目录在线程内的技能/hook行为。没有发送模型 turn、授予 hook 信任或配置沙箱。因此，完整插件等价性是**尚未证实**，不是已经否定。

本轮到此停止平台探索。全局 home 的直接 MCP 覆盖可验证载荷和原生执行，但不能替代完整插件发现/采用率验收。证据保存在 `next-profile-write-probe/receipt.json`、`next-capability-root-probe/receipt.json` 和 `next-capability-root-probe-mcp2/receipt.json`。

准备脚本只读历史文件、计算哈希，并在 NEW/tests 中写设计 JSON。三个测试验证失败行保留、完整重复计划不变，以及参考文件改变时必须拒绝复用。
