# Evidence delivery in 0.8

[中文](delivery-0.8.zh-CN.md)

Machine-facing evidence packets retain the existing source-line schema. The model-facing bridge may emit a `workflow-view`: paths/revisions appear once in a source table and evidence rows cite a source number plus their original line or pointer. The complete original emitted text is saved before this projection, including any MCP envelope; `ops_result(view="raw")` with `nextOffset` reconstructs it exactly. Projection never mutates the program's tool result.

Source selection distributes rows across files, prioritizes matching nonblank lines, and retains explicit stage errors, omitted stages and source cursors. Compact mixed-success document replies remain inline. A projected document response lists every request's status before excerpts, including nested per-file failures and any omitted failure count. Display clipping and row omissions remain explicit.

Document `read` requests automatically select existing DOCX/PDF/CSV/TSV readers. Routing metadata states the reader, source path, offset unit and any applied limit. Pure text multi-file reads keep their existing behavior. Mixed requests must normalize to at most four independent native reads, preserving the existing parallel batch and timeout boundary; oversized mixtures are rejected before execution and can be split explicitly.

Same-frame output allocations use a fair share, redistributing unused small-result quota. An unrelated large result therefore cannot claim most of the frame solely by its original size. Explicit raw retrieval, media and small complete results retain their existing paths. Recognized test/build/diagnostic/diff summaries take precedence over the generic native-observation view. Source-like output is not interpreted as a diagnostic log.

Working-set displays include available saved content, pending notes and per-source freshness. Investigation replies explicitly confirm when recovery is available later; sufficient evidence can be used immediately. Stale sources do not contribute old content. A fresh native read acquired during revision checking appears separately as `current-read`, with its own matching revision, bounded window and coverage. If its content exceeds the response budget, its fresh reference remains distinct from the old snapshot. Reused investigation results indicate how many revisions were checked, without assuming the model retained an earlier context.

Automatic verification metrics are recorded only when the final displayed preview actually contains the native-observation view and a known exit/session state. Computing a preview, retaining a small original result, or replacing that preview during frame budgeting does not count as automatic service. These observations do not establish a task-opportunity denominator.

The delivery regression run covers 134 tests across eleven owned modules. Its statement-and-branch CRAP calculation reports a maximum of 6 and no function above 6: [receipt](../verification/crap-delivery.json). This includes real native document reads, mixed success/failure handling, preserved semantic summaries, source/media handling, exact raw recovery and payload-free service accounting. Oversized source rows are counted as omitted without starving later implementation or test evidence that fits the budget. It is a component gate; complete runtime and paired model-cost acceptance are separate release gates.
