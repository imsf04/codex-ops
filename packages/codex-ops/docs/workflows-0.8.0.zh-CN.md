# Codex Ops 0.8 工作流契约

[English](workflows-0.8.0.md)。命令、审批、写入和轮询继续使用 Codex 原生权限链；公开 MCP 工具仍为八个。

## 直接调查

调用 `ops_workflow({root:"C:/project",question:"Where is retry_delay capped and tested?"})`。
可选 args 包含 anchors、paths、focus、maxBytes（4096..24576）。
focus 实际改变有界计划；目录范围中的测试、配置线索会增加对应角色，
显式文件路径不会扩大到同级文件。
新增 Rust 内核复用现有 dsh-ops core，一次进程处理复合只读请求；
普通文件操作仍使用原有 worker。

机器结果保留精确源码行、修订、覆盖和待处理阶段。
模型显示按文件去重来源信息，优先显示失败与遗漏；投影后提供完整原始输出引用，
程序内部值保持不变。已有可用证据时无需再取 raw。

## 文档与原生结果

`operation:"documents",args:{requests:[{operation:"read",args:{files:[{path:"policy.docx"}]}}]}`
将 DOCX/PDF/CSV/TSV 交给对应读取器，普通文本范围读取保持原有语义。
独立原生请求遵守既有有界批次契约；混合成功及嵌套文件错误优先显示。

长原生命令输出保留退出码、会话状态，并直接提供诊断证据，无需新执行命令或另调 verify。
已有测试、构建、TypeScript、差异、源码和媒体处理在适用时优先保留。
显式 verify 仍分析已观察的结果；可选 SDK 可以组合原生执行与有界轮询。

## 自动恢复源码证据

成功调查会为当前原生聊天、权限上下文和根目录保存证据。
`operation:"working_set",args:{action:"resume"}` 直接恢复最近的自动工作集，
无需先手动 save 或记住引用。显式 workingSetRef 继续选择手动保存的集合。

每个文件的选中行分别保存。恢复时重新检查引用权限与文件修订；
过期文件的旧行不会混入另一个当前文件的显示。不假定模型仍保留之前的聊天上下文。

文件改变时，同一次原生检查会返回已保存行附近的新证据，前后带两行上下文，最多 64 行；
原位置未知时返回有界的文件开头。`currentEvidence` 标明当前修订，旧快照仍标为过期，
不将局部窗口说成整个文件已经刷新。若结果预算容不下新证据，`currentEvidenceRef`
保存这次新读取的完整结果，可直接取回，无需重新读取文件。自动保存状态明确表示供后续使用，
当前已返回的证据可直接用于完成任务。

显式文件范围内完全相同的重复查询，可以在一次原生批次修订检查后复用观察。
目录查询仍重新搜索，以发现新文件。没有可信聊天标识时不启用自动跨调用恢复。
沿用现有 TTL 和存储配额；工作集存储不可用时，新的调查仍可返回证据。

## 计量

ops_stats 支持带时区的 since/until 和原生 turn_id。
真实聊天 token 与按版本、用途区分的工作流/worker 事件分别报告；
外层调用、原生动作、worker 启动是不同边界。
调用完成、取得有效证据、独立标注的适用机会分别计数。

自动交付诊断、自动复用证据与显式选择工作流分别报告。
没有机会分母时采用率保持未知；事件丢失和保留期限的限制可见。
计数器不能直接证明净节省；模型对照需要同时记录失败、缓存/未缓存输入，
并采用真实按需插件、hooks 与 skill 条件。

Rust 内核没有增加命令执行器或常驻服务；引用权限不会因恢复旧证据而扩大。
