# Codex Ops 0.7：从我的实际使用倒推设计

调查日期：2026-10-29。本文是下一版建议，未开发或安装 0.7。
[English](research-v07-experience.md) · [GitHub 一手研究](research-v07-github.md)

## 要达到的体验

我应能说清要解决的问题，得到足以推进任务的证据；无需先学习目录、选视图、解析
MCP 信封、分页取回、裁切文本，再把资料重新拼起来。一次有用调用替代多步，
比增加插件调用频率更有价值。自动输出处理、显式调查入口、原生执行共用同一证据内核。

本次调查就出现了真实摩擦：普通文件读取经压缩变成引用，随后需要再次读取引用；
locate 的完整 MCP 信封被直接输出后又被捕获。0.6.1 对小 documents/diagnose 的
直返修复有效，但还没有覆盖所有有用的中等结果和显式调查。应解决交付契约，
而不是简单把全部输出阈值调高。

## 实际采用与成本

审计窗口为北京时间/新加坡时间 10 月 28 日 15:29:08 至 29 日 15:29:08。
扫描两天目录共 33 个 rollout；按 response/call/item ID 去重，沿 parent/fork 链将
插件开发及其子 agent 分组。本次调查不计入采用率。原始聊天正文不复制进报告。

| 范围 | 有动作会话 | 原生命令+MCP+文件修改 | ops_result | ops_workflow |
| --- | ---: | ---: | ---: | ---: |
| 其他业务：4 个独立聊天，含其子 agent | 8 | 851 | 50 | 0 |
| 插件开发及验收，含子 agent | 16 | 1,347 | 55 | 4 |
| 0.6.1 安装后的其他业务子集 | 1 | 273 | 17 | 0 |

更早的中途统计只排除了插件主会话，混入插件子 agent；本文采用修正后的口径。
8 个会话不是 8 个符合工作流条件的任务，所以只能报告观察到 0 次自然采用，
不能计算“符合条件机会的采用率”。两个日期目录之外的历史聊天不在扫描范围。
安装时间也不是每个进程已经换版的证明。

唯一安装后业务样本确实收到含 ops_workflow/logPath 的自动运行时指导，并看见 0.6.1
技能描述，但没有调用工作流。233 次命令按启发式分类为 108 次含文件读取、22 次搜索、
23 次测试/构建、24 次网络/远程、56 次其他；复合命令不能据此直接自动替换。
17 次回读涉及 13 个引用，16 次 raw、1 次 items，未采用已有 batch 回读能力。

该业务样本有 137 次模型请求：累计输入 19,756,310 token，其中缓存输入 19,574,144，
未缓存输入 182,166；首末请求输入分别为 27,334 和 224,550。
这些是实耗，既不是 peak context 的通用结论，也没有同任务关闭插件的对照，
不能计算插件节省的 token 或金额。输入不断增长表明仍有优化空间，但不证明增长由插件导致。

当天 presentation 快照：2,936,239 → 2,188,712 UTF-8 字节，减少 747,527（25.5%）。
计数含开发/验收，不按 0.6.1 分版；不能把这个百分比当成 token/账单节省。
50 次 retrieval accounting 共 292,892 返回字节，其中 2 次同页重复。
此前 0.6.1 受控试验的 10 个共同成功配对仍是唯一可引用的配对成本证据：
动作减少 24.2%，累计输入减少 21.9%，配对输入变化中位数仅 -3.8%；
两组均 11/12 严格任务成功，不能省略失败。

## 0.7 的六个完整方向

### 1. 一个问题直接换来调查证据（最高优先级）

提供直接可发现的调查入口：必要输入为 root 和 question，允许可选 files/refs。
内部组合已存在的搜索、上下文、文档和日志能力；无需先 catalogue/SDK。
例如“发布版本从哪里读取，哪些地方会覆盖？”一次返回定义、调用者、配置覆盖、
相互矛盾的证据、文件行号及未查范围。先用确定性检索/排序与有界阶段，
不默认启动额外模型或递归 agent。问题不能解析时给一个明确可补参数，避免泛泛失败。

原生读工具仍可用。自动层能识别的结果直接得到同样的证据呈现；
不为提高工作流采用数字强行改写任意 PowerShell 或增加 MCP 绕路。
验收：从搜索到可修改位置的模型往返减少；未强制指定工具的任务里自然选择率上升。

### 2. 一次交付够用的内容，自动避免“压缩—取回—重包”

默认交付相关源码范围、日志根因块、表格整行与列名，并标明上下文是否齐全。
中等有用结果使用共享预算选择相关内容，而非一律变成引用。
所有有界显式检索/工作流结果统一识别，不再要求调用者手工 unwrap 不同信封。
程序内值保持完整；错误、多媒体、退出码和会话 ID 保持原生。
必须全文阅读的指令文件遵守其阅读要求，不能用摘要丢掉约束。

已有 batch/find/items/count/group 自动进入常见路径；不给每次调用打印整本说明书。
验收：减少因展示裁切而立即补读的次数；原文仍可精确恢复；数据完整性不过关不发版。

### 3. 多来源的按问题检索，找得到也解释查了什么

为已获取的证据建立可回溯索引，先做 FTS/BM25 与精确字段/符号定位，
支持一次查询多个引用、文件或文档；现有 batch retrieval 是基础，不算新功能。
返回来源位置、匹配上下文、未覆盖部分和互相矛盾的候选；
不能用命中数暗示全源已查完。文档需保持行、表头、页码等来源结构。
按当前 chat/权限/版本重新校验，引用本身不授予额外读取权限。

不要默认 LLM 摘要或 embedding 网络请求；只有配对实测证明收益后才考虑。
验收：同样问题下 raw 回读比例及补查轮数下降，预埋反例仍能被发现。

### 4. 原生验证闭环：跑完、等完、定位失败一起完成

在现有 native execution 和任务恢复基础上补测试/构建结果编排：
增量进度、最终退出状态、失败组、关联源码、下一条有依据的验证入口。
命令经原生执行器和既有权限；只读 MCP 不偷偷启动写操作或测试。
优先 pytest/npm/cargo/git 的确定性解释；保留未知输出原文。
已存在的 polling、diagnose、task lifecycle 不重新包装成“首次实现”。

同时解决真实阻力：CWD/父目录访问失败的分类、正确路径建议、运行状态偶发不一致的解释。
不能用提权、盲重试或把失败记成成功来降低调用数。
验收：每个失败路径保留原始诊断；无意义的重新运行/轮询下降。

### 5. 可恢复的任务证据与工作集

维护简短任务状态：已证实事实、来源修订、未决问题、已做动作、待验收点；
按需构造恢复卡片，避免重启/压缩后重新搜一遍。支持文件更新后的定向失效。
这是源证据缓存和恢复机制；不把已有 explicit incremental 或同帧去重算新能力。

跨模型轮次去重仍需实际上下文可见性的证据。文件没变不代表模型仍看得到旧内容。
不能确认可见性时交付自包含证据或显式取回，不擅自删除历史上下文。
建议先交付 provenance + invalidation + resume，再以实验开关验证跨轮优化。

### 6. 以整项任务成本为目标自动调节

建立会话/轮次实耗账本：模型请求、外层 exec、原生命令/MCP/文件修改分别统计；
累计输入、缓存输入、未缓存输入、输出、时延、失败、返工分别统计。
自然采用区分 eligible/opportunity/selected/completed/fallback，单独列开发验收。
不要用所有工具调用作为工作流采用率分母，不把减少字节换算成已省账单。

根据本会话是否频繁立即回读调节证据预算：裁太狠就多给一点，重复噪音就少给一点。
总成本应包括取回、额外索引/模型调用、失败重试、校验和延迟。
策略先影子观察与离线回放，之后再启用有证据的策略；工作流次数可以下降，只要成功任务更便宜。

## 与 dsh-ops 的定位

上游 v0.4.4 与 main 的能力不同，不能按版本号大小比较。
它仍领先于我们的宿主原生工具替换、动态 PTC 注册、侧栏和跨平台产品化。
我们已有自动 Code Mode 外层呈现且不改变内部值、小结果直返、复合证据、
有序依赖阶段/恢复；这些是已有实现，不是已证实全面优于上游。

0.7 应争取在“给定任务的一次性证据交付、自然采用、真实全链路成本”上超越，
而不是再造 functions.exec 或对齐工具数量。上游也正在修批量读取和 Windows
搜索成本；不能把 open issue/PR 算进已发布能力。

## 验收与实施顺序

第一批把方向 1+2+6 做成完整闭环；第二批加 3+4；第三批完成 5 的恢复工作集。
不等全部做完才看用户体感，每批都用相同任务与 0.6.1 对照。

建议冻结验收后再编码：至少 12 类任务 × 3 次配对，包含真实目录、错误路径、
权限拒绝、晚出现错误、文档反证、长任务、恢复和多 agent；两组注入指令一致，
不点名要求调用插件。保留全部失败与成本，不事后降低完美通过门槛。

大胆目标（不是已测收益）：共同成功任务的总动作再降 25%、累计输入再降 20%、
未缓存输入不升、因展示造成的立即补读至少减半；同时报告全尝试总量、中位数、
各任务和长尾，不让单个大收益掩盖普遍退化。样本太小则不宣称总体质量等价。
所有生产函数继续 CRAP ≤6，协议、原始值、权限和完整性回归必须通过。
最后用实际日常任务的机会采用率校验，不能只依赖人工强制工作流演示。
