# Codex Ops 0.8 原生调用、采用与成本验收

[English](benchmark-0.8.0.md)。重新比较0.6.1、0.7.0与0.8.0；旧版失败和冻结目标记录不改判。

## 条件与规模

[计划](../verification/acceptance-v080.json)包含132次尝试：12个旧任务×3版本×3次，加4个新任务族×2版本×3次。任务不点名要求OPS。旧答案判定不变，已有receipt-lf1生产脚本修正继续明确记录。

使用各版本实际暂存运行时、原生插件、对应受信任hooks及原生skill目录，不提前注入完整SKILL。配置受信任与真正执行分别核对，记录实际hook事件和skill读取。

Windows沙箱账户属于整台机器，因此共用一个私有权威CODEX_HOME，以每进程配置只启用一个版本。源码、运行时和每次观察存储独立；试验中不分别重新配置沙箱账户。验收后由发布负责人通过官方机制恢复桌面端沙箱状态。

合成任务位于C:/Temp/CodexOpsAcceptance-v080。认证、RPC/schema日志、原始事件、预期答案、观察存储及验收源码均在任务搜索目录之外。每次模型调用前检查原生启动未改变任务文件清单。[隔离检查](../verification/v080-workspace-isolation.json)实测PowerShell工作目录，并通过真实Rust搜索确认找不到日志/答案标记；不声称workspace-write禁止所有外部读取。

## 指标

- 外层模型工具调用、原生命令/MCP/文件变更动作分别计量。
- 透明观察器记录MCP服务真正启动的worker，并验证与直接服务的目录和返回值一致。原生变更CLI另启的worker不在此边界内，不用零替代缺失观测。
- 输入、缓存输入、未缓存输入、输出分别报告，不从字节压缩推算token或费用节省。
- 适用任务标签按调用前的任务要求确定，也承认旧locate/incremental入口。区分选用、首个原生工具、结构性证据与严格成功。
- 自动保存只表示证据可用；只有真实复用或真正交付的验证预览进入自动服务统计。没有独立机会分母的生产计数不换算成日常采用率。

主要成本比较采用共同成功任务，同时保留全部尝试、失败、缺失观测和基线成功/候选失败配对。缺少原生或模型测量时，成本门槛为UNKNOWN。

## 门槛与执行

新0.8相对新测0.6.1：原生动作至少减少25%、输入至少减少20%、未缓存输入不增加、成功数不降低；另报告相对0.7的增量、质量不退步和未缓存输入不增加。35%/30%仅为非阻断探索目标。成本检查不单独批准发布，CRAP、原生协议、安装与失败复核仍须通过。

Pilot共10次：代码定位、冲突文档各3版本；两轮变更恢复、延迟失败各0.7/0.8两版；均一次。它不替代132次完整验收。新付费轮次开始前保存验收源码副本与源码/配置/运行时指纹，不替换同一报告中的失败或中断尝试。

第一轮pilot在2次后停止，不用于验收；保留原始结果和[已知消耗](../verification/v080-pilot-1-invalidation.json)。它同时揭示真实证据选择问题，修复后独立重新冻结候选。下一轮使用新报告、目录和指纹。

运行tests/run_v080_costs.py时明确区分私有--run-root与普通--workspace-root。默认串行，可选2/3个独立进程。停止标记阻止新提交，已启动尝试继续收尾并保留。恢复不能重跑在途尝试，也不能改变源码、配置、顺序、模型、推理强度或并发数。
