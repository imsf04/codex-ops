# 0.8 证据交付

[English](delivery-0.8.md)

程序内部的证据包保留现有源码行结构。模型侧桥接可以显示 `workflow-view`：路径与修订信息在来源表中只出现一次，证据行用来源编号和原始行号或指针引用。投影前保存完整原始输出，包括 MCP 信封；通过 `ops_result(view="raw")` 和 `nextOffset` 可以精确恢复。投影不修改程序内部工具返回值。

源码行分配兼顾不同文件，优先选择命中且非空的内容，保留阶段错误、未执行阶段及来源游标。已经足够短的文档混合成功结果继续直接返回。投影后的文档响应先显示各来源状态，再显示正文片段；同一次多文件读取内部的错误也单独显示，并标明未显示的错误数量。显示截断和省略行数都有明确标识。

文档 `read` 请求根据 DOCX、PDF、CSV、TSV 格式选择现有读取器。路由信息说明实际读取器、路径、偏移单位及应用的数量限制。纯文本多文件读取保持原有行为。混合请求最多转换为四项独立原生读取，保留已有并行批处理和超时边界；超过范围时在执行前明确拒绝，可拆为下一次请求。

同一输出帧按公平份额分配显示预算，并重新分配小结果未使用的份额。大结果不会仅凭原始体积占用大多数预算。明确要求的原文取回、媒体及较短的完整结果保持现有处理路径。已经识别出的测试、构建、诊断及差异摘要优先于通用原生观测视图；源码文本不会被解释为错误日志。

工作集显示包含仍有效的保存内容、待核验说明及逐来源的新鲜度。调查结果明确说明是否已保存、可供以后恢复，证据足够时可直接完成任务。过期来源不会再次显示旧正文。修订核验过程中取得的新原生内容另标为 `current-read`，携带独立且匹配的修订、有限读取窗口和覆盖信息。新内容超出响应预算时保留其独立原文引用，不会把旧快照作为当前内容。复用调查结果时说明核验了多少项修订，不假定模型仍记得旧上下文。

仅在最终交付的预览确实包含原生观测视图和已知退出码或会话状态时，记录自动验证服务事件。仅计算了预览、保留小型原始结果、或在帧预算处理中替换掉该预览，都不计入自动服务次数。这些事件不能自行产生适用任务的分母。

组件回归共134项测试通过，覆盖11个负责模块；按语句与分支覆盖计算的 CRAP 最高为6，没有函数超过6：[记录](../verification/crap-delivery.json)。验证包括真实原生文档读取、部分成功和错误、已有语义摘要、源码与媒体处理、精确原文恢复及不含正文的服务计量。超预算的源码行计入省略数，同时继续保留后续仍能容纳的实现与测试证据。完整运行时和真实模型配对成本仍由发布验收单独判断。
