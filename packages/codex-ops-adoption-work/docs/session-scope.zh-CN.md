# 引用归属

新的 MCP 引用依据原生请求中的聊天身份绑定，不接受工具参数声明的身份。
可取得的沙箱与审批元数据参与权限指纹；权限指纹改变后，MCP 无法读取旧引用。
去重键包含归属，不同聊天即使内容相同也不会共享引用。释放引用与读取使用同样检查。

Code Mode 自动输出引用绑定到原生运行时管理进程。Code Mode 会话 UUID 并不是聊天 ID，
实现不猜测两者关系。同一运行时内的聊天持有引用即可取回，其他运行时被拒绝。
因此重启运行时可能在存储 TTL 到期前使引用不可访问。旧版 0.5 引用仍沿用原来的当前用户
bearer 行为直到过期。新的 MCP 请求缺少聊天身份时绑定到已验证运行时，否则绑定本机
MCP 服务进程；可执行引用计划必须具有原生聊天身份。内部库调用不声称具有宿主身份，
实现不会从运行时 ID 猜测聊天归属。

直接 PostToolUse hook 存档和内部库存档仍采用当前用户持有式引用，不声称具有原生 MCP
权限指纹。上文具有运行时归属的自动输出路径专指 Code Mode 桥接。

原生命令加载计划时检查执行环境提供的线程 ID；执行仍遵守 Codex 当前的沙箱与审批策略。
引用、元数据和计划都不授予文件访问权限。任务日志依靠显式工作区的原生权限保护。

这些是应用层归属检查，不防御以同一系统用户身份运行的恶意进程。该用户仍可访问本机
存储路径与工具客户端。引用读取失败不能作为重跑修改操作的理由。

使用 `python doctor.py --check-files` 或 `ops_stats(check_runtime=true)` 查看插件版本、
已配置入口和观察进程真正关联的运行时版本；按需检查暂存文件哈希。hook 信任以原生
`hooks/list` 为准，不根据文件存在或插件自己的声明推断。
